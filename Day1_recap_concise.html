Business significance

A compromised tool or build pipeline can turn an AI agent’s access into an attack path. This lab provides a repeatable way to test whether controls block that path—and whether monitoring detects activity that gets through.

What remains unproven

Identity hijacking and credential harvesting scenarios remain untested. Azure and standalone AWS variants are built but not live-validated. Production readiness also requires artifact signing and provenance, audit retention, incident response, and named control owners.

Recommended next decision

Authorize a bounded validation phase with a named security owner.

  1. Test identity and credential scenarios on the agreed lab targets.
  2. Extend live validation to the Azure and standalone AWS variants.
  3. Set production acceptance criteria for prevention, detection, evidence retention, and response.
Scope: disposable lab infrastructure; no production systems touched, as reported in the source recap. Technical evidence reference: Documentation_Kubernetes.md and the Day 1 GitHub test record.
