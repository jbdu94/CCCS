What's new, and how each new check works

The three original checks are unchanged in logic (see the base report for those). Here's what production mode adds.

SUSPICIOUS_IMPLEMENTATION_PATTERN SIGNATURE — HARDENED

Same keyword list as before, but the text is normalized first: the exact homoglyph substitution and the exact multi-line split this lab's own research demonstrated are both folded/collapsed away before matching.

folded = "".join(HOMOGLYPH_FOLD.get(ch, ch) for ch in text) collapsed = re.sub(r"\s+", " ", folded)

Verified with a self-test every time this file runs directly: both bypass payloads are re-generated from the lab's own research module and confirmed caught before any real detection runs.

UNAUTHORIZED_ACTOR_CHANGE IDENTITY / ACCOUNTABILITY

Every registration and description-change event now carries an actor field. This run's attack script never authenticated as anyone, so it defaulted to "unknown" — which is never on the approved list, so it's flagged automatically rather than silently trusted.

if actor not in APPROVED_ACTORS: flag("change made by an unrecognized actor")

This is the fix for a gap the base report named directly: the original three checks could tell you a description changed, never who changed it.

AUDIT_CHAIN_INTEGRITY TAMPER EVIDENCE

Every event is now hash-chained: each entry's hash covers its own content plus the previous entry's hash. Editing or deleting a past entry breaks the chain from that point forward. Checked first, before any other finding — if this fails, nothing else in the run can be trusted at face value.

expected_hash = sha256(seq, timestamp, event_type, details, prev_hash) chain_valid = (event.hash == expected_hash)

Proven, not assumed, twice over: tested by editing a real logged event afterward and confirming this check catches it at the exact broken entry (see the base documentation), and now confirmed clean against 3 real, untampered events from this exact run.
