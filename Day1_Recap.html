The risk this addresses

AI agents are being connected to real business systems — tool registries, CI/CD pipelines, cloud credentials — faster than security controls are keeping pace. A single poisoned tool definition, a compromised build pipeline, or a stolen credential can turn a helpful AI agent into an attack path into the business. This is not theoretical: it's now tracked as its own category by OWASP and referenced directly in NIST's AI risk guidance.

What we did about it today: built a repeatable testing capability that simulates these exact attack patterns and proves — on real cloud infrastructure, not simulated systems — whether our defenses actually catch them.

What this is worth

Tested against real infrastructure, not a demo

Attacks ran against a real Kubernetes cluster on AWS EKS and a real GitHub repository — the same class of systems a production AI deployment would actually use. A result here means something in a way a slide deck never could. (Azure and standalone-AWS targets are built and ready; today's live runs were on Kubernetes and GitHub specifically — see the detail tables below for exactly what's tested versus what's built.)

Both halves of defense proven, separately

Confirmed our prevention layer blocks a real malicious action in real time, before it happens. Separately confirmed that when prevention isn't in the path, detection still catches the attack immediately afterward, from real telemetry. Neither claim is assumed — both are demonstrated.

An honest maturity picture, not a sales pitch

Compared what we built against what a real enterprise security program requires — grounded in NIST's AI Risk Management Framework, Zero Trust architecture, and software supply-chain integrity standards (SLSA). We know exactly what's proven and what's still an organizational decision, not a code problem. See the scorecard below.

External validation underway

Collaboration started with the Canadian Centre for Cyber Security (CCCS) to run this against their infrastructure — independent validation of these results, not just an internal claim.

Proven on the platform CCCS actually uses

Confirmed today, live: a real, authenticated commit against a real GitHub repository, correctly caught by this lab's UC4 detector — the same script, unmodified, run directly against the real telemetry that commit produced. GitHub is the platform this CCCS workshop runs on — this is direct evidence, not an assumption it will translate.
